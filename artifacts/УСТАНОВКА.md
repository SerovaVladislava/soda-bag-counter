# Система подсчёта мешков с содой — установка

Комплект для переноса на другой компьютер. Готовые образы Docker уже внутри,
собирать проект заново не нужно.

## Что входит в комплект

| Файл | Назначение |
|---|---|
| `rtsp-bag-counter-images.tar.gz` | Образы Docker: backend с моделью и MediaMTX |
| `docker-compose.yml` | Запуск обоих сервисов |
| `mediamtx.yml` | Конфигурация RTSP-сервера |
| `data/uploads/` | Рабочий каталог: история, архив кадров, логи |

## Требования

- Docker Desktop (Windows или macOS) либо Docker Engine с плагином Compose (Linux).
- Свободные порты `18000` и `8554`.
- Около 8 ГБ свободного места на диске.

## Установка

1. Распакуйте архив `soda-bag-counter-v1.0.zip` на целевом компьютере.

2. Откройте терминал в получившейся папке и загрузите образы:

   ```bash
   docker load -i rtsp-bag-counter-images.tar.gz
   ```

   Загрузка занимает несколько минут. По завершении проверьте, что образы на месте:

   ```bash
   docker images
   ```

   В списке должны быть `rtsp-file-stream-tester-backend` и `bluenviron/mediamtx`.

3. Запустите сервисы:

   ```bash
   docker compose up -d
   ```

4. Откройте в браузере `http://localhost:18000`.

## Как пользоваться

Интерфейс состоит из двух вкладок.

**RTSP-поток** — основная рабочая вкладка:

1. Раскройте блок «Управление RTSP-потоками» вверху страницы.
2. Через форму добавьте RTSP-ссылку камеры, например `rtsp://192.168.1.50/live`.
3. Нажмите «Анализировать» напротив нужного потока.
4. Система начнёт считать мешки, опускаемые краном в бункер. Одновременно можно
   анализировать два потока.

Выше расположены итог за сменовый день и карточки мониторов с текущим счётом.
Ниже — история по сменам с выгрузкой в Excel.

**Кадры с разметкой** — проверка работы модели. Каждый раз, когда система засчитывает
мешок, она сохраняет кадр с отмеченной зоной над бункером. Кадры сгруппированы по датам
и времени, их можно отфильтровать по периоду и по потоку.

## Смены

Сменовый день считается по времени площадки (Екатеринбург): дневная смена с 07:00 до
19:00, ночная — с 19:00 до 07:00. Мешки, посчитанные ночью после полуночи, относятся к
предыдущему сменовому дню.

## Управление

Остановить:

```bash
docker compose down
```

Перезапустить только backend:

```bash
docker compose restart backend
```

Посмотреть логи:

```bash
docker compose logs -f backend
```

## Хранение данных

Всё, что накапливает система, лежит в папке `data/uploads` рядом с `docker-compose.yml`:

- `rtsp_stream_history.json` — список добавленных RTSP-потоков;
- `bag_shift_history.json` — история подсчёта по сменам;
- `bag_detection_frames.json` и `detections/` — архив кадров с разметкой;
- `ffmpeg.log` — лог публикации потока.

Кадры хранятся 30 дней, но не более 3000 штук — старые удаляются автоматически.
Для резервной копии достаточно скопировать папку `data/uploads`.

## Настройка под другую камеру

Счёт привязан к положению бункера в кадре. Зона, по которой определяется мешок, задана
в долях кадра в файле `backend/app/analytics.py`:

```python
ZONE_ABOVE_HOPPER = (0.490, 0.000, 0.680, 0.212)
```

Это прямоугольник над горловиной бункера: левый край на 49 % ширины кадра, правый на
68 %, от верхней границы кадра до 21 % высоты. При смене камеры или её положения эти
значения нужно пересчитать под новый ракурс, иначе система перестанет считать.

Остальные пороги (`ZONE_FILL_ENTER`, `ZONE_ABSENCE_SECONDS` и прочие) заданы там же
и вынесены в параметры, поэтому подстраиваются без изменения логики.

## Если что-то не работает

**Порт занят.** Измените левую часть в `docker-compose.yml`, например `"18080:8000"`,
и откройте интерфейс по новому адресу.

**Интерфейс открывается, но поток не анализируется.** Проверьте, что RTSP-ссылка
доступна с этого компьютера:

```bash
ffplay -rtsp_transport tcp rtsp://адрес-камеры/поток
```

**Счётчик не растёт.** Откройте вкладку «Кадры с разметкой». Если кадров нет, модель не
видит мешок в заданной зоне — скорее всего, нужно пересчитать координаты зоны под
ракурс вашей камеры (см. раздел выше).
